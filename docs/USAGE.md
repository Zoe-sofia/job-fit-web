# 使用说明

## 一、三分钟上手

1. **贴简历**：左侧「粘贴文本」，或切到「上传文件」拖入 PDF / DOCX / TXT。
2. **贴岗位**：右侧填岗位名称、公司、地点、薪资（四项必填），再把 JD 原文整段粘进「岗位描述」——**不需要整理格式**，原样贴。
3. **选视角**：自己投递选「我是求职者」，筛人 / 面试选「我是面试官」。选完不用重跑，已出的报告会就地换措辞（分数不变）。
4. **点「开始匹配分析」**：默认本地引擎，约 1 秒出结果。
5. **看结果**：先看视角面板的结论，再核对硬性条件，最后看维度分与证据。
6. **回看记录**：每次分析、每次切换视角都会在下方记录区新增一条独立记录，按岗位分组，随时点开对比（见下节）。

选填项（公司规模、经验筛选、学历筛选、技能筛选、福利、来源链接、行业、法人）不是装饰：填了之后硬性条件判定会从 `unknown` 变成 `pass` / `fail`，准确性明显提升。

## 二、怎么看结果

### 两个分数

| 分数 | 含义 | 怎么用 |
|---|---|---|
| **匹配度**（大字） | 受硬门槛约束的最终分 | 决定「投不投」 |
| **不考虑硬性条件约束的综合评分** | 全维度加权、不封顶 | 决定「值不值得争取」 |

典型组合：

- 匹配度 44 / 综合 72 → 硬门槛卡住了（常见于年限差半年、学历差一档、跨城市）。**这是最值得内推、写求职信、主动沟通的一类**。
- 匹配度 58 / 综合 58 → 没有硬伤，但整体契合度一般。改简历的收益有限，不如换岗位。
- 匹配度 44 / 综合 40 → 能力本身也不够。别浪费时间，先补能力。

### 置信度

`置信度 100%` 表示四个维度都有证据支撑；`50%` 表示只有一半权重的维度能评分。**置信度低时，先补简历信息，再看分数**——否则分数是拿半份简历算出来的，参考价值有限。

### 技能明细表

| 判定 | 含义 | 该怎么改 |
|---|---|---|
| 有证据（matched） | 技能出现在项目/经历描述里，且有上下文 | 保持 |
| 只有名词（partial） | 只出现在技能清单，没有使用场景 | **最高优先级**：移到项目段落，补一句「用它做了什么、结果如何」 |
| 缺失（missing） | 简历里找不到 | 真有就补证据，没有就别硬编 |

> 只会写「熟悉 Vue」的人很多，能写「用 Vue 重构订单页，首屏从 2.4s 降到 0.9s」的人很少。前者在筛选里等于没写。

## 三、看分析记录

记录区在结果下方。**每次分析都单独存一条**，同一岗位的多次分析、同一份结果的多个视角都是一条独立记录，互不覆盖：

| 情况 | 记录行为 |
|---|---|
| 同一岗位再分析一次 | 新增一条（第 2 次、第 3 次…），旧记录原样保留 |
| 分析完切到另一个视角 | 视角变了就是另一份结论，单独新增一条，不改写上一条 |
| 刷新 / 关掉再打开 | 记录还在（默认保存在本机浏览器） |
| 删除某一条 | 只删这一条，同岗位其他记录不受影响 |

列表按岗位分组。组头一行写明：该岗位共分析几次、求职者 / 面试官各几条、最高分、最近一次时间。组内按时间倒序，每条标了「第 N 次分析 · 视角」，下面跟着生成时间、引擎、档位与分数。

点任意一条打开完整记录：岗位信息（含 JD 原文）、匹配结论、双评分、维度分、硬性条件、技能明细、视角段落，以及**记录编号、该岗位第几次、生成时间**。底部两个动作：

- **载入到表单**：把这条记录的岗位信息和**当时的分析视角**一起填回输入区，改完再分析。
- **删除此条记录**：只删这一条。

记录区右上角还有：

- **导出 Excel**：下载 `offerfit-records-YYYY-MM-DD.xlsx`，含全部记录与已删除标记。字段、顺序、内容与旧版 JSON 导出完全一致，只是改成多张工作表：

  | 工作表 | 用途 |
  |---|---|
  | 导出说明 | schema、条数、导出时间，以及各表字段与取值说明 |
  | 分析记录 | 每条记录一行，列顺序即 JSON 里 record 的键顺序（`job.*`、`result.*` 按点号展开） |
  | 维度得分 / 硬性条件 / 建议清单 / 视角内容 / 匹配要点 / 技能明细 | 数组字段逐条一行，带序号；表头冻结并带筛选，数值列可直接排序求和 |
  | 已删除记录 | 墓碑 id |
  | 记录JSON | 逐行原文（无表头），字段与顺序同旧版 JSON 导出 |

  需要跨设备共享时，把「记录JSON」工作表整列复制、另存为 `data/records.json` 后提交即可。
- **清除记录**：整批删除，会二次确认。

设置里的「把分析记录保存在本机浏览器」默认开启；关掉后新记录只写当前标签页（关闭即失效），**已有记录不会被清掉**。记录最多保留 200 条，存满时优先丢最旧的并给出提示。

## 四、选择分析视角

页面第三步「分析视角」决定报告的**组织方式**，不影响任何分数：

| 视角 | 适合谁 | 报告里会多出什么 |
|---|---|---|
| 我是求职者（默认） | 自己投递、改简历 | 匹配优势 / 能力差距 / 简历优化方向 / 投递建议 / 面试准备建议 |
| 我是面试官 | HR、用人经理、面试官 | 候选人胜任度 / 岗位匹配证据 / 风险点 / 面试提问建议（每条附观察点） |

几条实用规则：

- **切换视角不改分数**：匹配度、综合评分、维度分、硬性条件判定在两种视角下完全一致。变的是措辞与建议的取舍。
- **求职者视角**看完顺序建议：优势（面试讲什么）→ 差距（先补哪个）→ 简历优化（改哪几句）→ 投递（投不投、怎么谈）→ 面试准备（准备哪个案例）。
- **面试官视角**把「改进建议」收起（那是写给候选人的），改为给出可直接照读的提问清单；每条问题后面的观察点说明「答成什么样算过关」。
- 分析完再切视角不必重跑：输入没变时页面会就地刷新建议段落；如果改过简历或 JD，会提示你重新分析，避免建议与分数对不上。

## 五、调整口径

「分析配置」区可以改：

- **维度权重**：觉得技术更重要就调高，合计需为 100（有「按比例归一到 100」按钮）。
- **评分阈值**：四个档位的分界线，必须严格递减。
- **硬性条件开关**：关掉某一项，它就不再触发封顶。例如应届生可以关掉「经验年限」。
- **输出格式**：详细报告 / 精简结论 / 结构化 JSON。

配置存在浏览器本地，下次打开仍在；「恢复默认」可清空。「清除全部数据」连记录一起清。

## 六、用 AI 模式（可选）

1. 引擎切到「AI 模型 API」。
2. 填三样：Base URL（如 `https://api.deepseek.com/v1`）、模型名（如 `deepseek-chat`）、API Key。
3. 点「测试连接」确认通。
4. 本地模型（Ollama）没有密钥时，勾「该接口无需密钥」。

常见失败与处理：

| 现象 | 原因 | 处理 |
|---|---|---|
| 请求被拦截 / `Failed to fetch` | 对方不允许浏览器跨域（CORS） | 换成允许跨域的接口，或切回本地引擎 |
| 线上打不开 `http://` 接口 | HTTPS 页面禁止混合内容 | 接口必须是 `https://` |
| 401 / 403 | 密钥错误或额度用尽 | 检查密钥与余额 |
| JSON 解析失败 | 模型输出格式漂移 | 已自动修复并重试一次；仍失败会提示，切回本地引擎即可 |

**密钥只存在内存里**，刷新页面就要重填——这是刻意的设计，不是 bug。

## 七、导出与分享

- **复制 JSON**：结构化结果，便于二次处理或喂给别的工具。
- **下载报告**：Markdown 文件，含维度明细、证据、缺口与建议。

导出内容**统一走脱敏**。但请注意：职位 + 公司 + 时间线的组合仍可能指向具体个人，公开分享前自行判断。

## 八、常见问题

**Q：为什么 PDF 拖进去没反应？**
A：直接用线上地址（<https://zoe-sofia.github.io/job-fit-web/>）就不会有这个问题——pdf.js 的解析线程在 `file://` 下会被浏览器拦截，必须是 http(s) 才能工作。若确实要本地跑，用 `python3 -m http.server 5180` 起服务后访问 `http://127.0.0.1:5180/`（见 README「开发与测试」）。另外扫描件 PDF（图片型）提取不到文字，请改用粘贴。

**Q：会上传我的简历吗？**
A：不会。默认状态下页面不发起任何外部请求。只有你主动开启 AI 模式，才会把**已脱敏**的文本发往**你自己填的**接口。详见 [PRIVACY.md](../PRIVACY.md)。

**Q：分数和某招聘平台给的不一样？**
A：口径不同。这里衡量的是「简历文本与 JD 文本的字面契合度」，且硬门槛单独处理。分数高低不等于录用概率。

**Q：换视角后分数会变吗？**
A：不会。视角只重组建议段落与结论措辞，匹配度、综合评分、维度分、硬性条件判定完全一致。如果换了视角发现建议和分数对不上，多半是简历或 JD 改过但没重新分析。

**Q：能批量分析多个岗位吗？**
A：可以。每次分析都独立存一条记录，按岗位分组展示，不同岗位不会互相覆盖；把岗位依次填进来分析即可，之后在记录区横向回看。目前没有「一键批量导入多份 JD」的入口。

**Q：数据能导出备份吗？**
A：记录默认保存在本机浏览器（`localStorage`），关掉页面不会丢，也可以「导出 Excel」把全部记录导成 `.xlsx`（含明细工作表与逐行 JSON）；单份结果另有「下载报告」（Markdown）与「复制 JSON」。若关掉「把分析记录保存在本机浏览器」，新记录只留在当前标签页，关闭即失效。

**Q：为什么导出从 JSON 换成 Excel 了？**
A：记录要能直接看、能筛选排序。`.xlsx` 里「分析记录」表的列顺序与 JSON 完全一致，另附「记录JSON」工作表保存逐行原文；需要回灌仓库基线时整列复制即可，字段、顺序与内容没有任何变化。

**Q：为什么同一个岗位会看到好几条记录？**
A：这是刻意的。每次分析、每次切视角都可能改变结论，保留每一条才能对比「改简历前」「换视角后」的差别。列表里用「第 N 次分析」和视角标签区分，点开就是当时那份完整结果。
