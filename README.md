# OfferFit · 简历与岗位匹配分析

把简历和岗位描述拆成**四个维度**逐条对齐：先判硬门槛，再算匹配度，最后按「你是求职者还是面试官」给出对应的结论与行动清单。

**全部计算在浏览器里完成**——简历不上传、不落盘、不埋点。没有后端，没有构建步骤，没有外部 CDN。

> 在线使用：<https://zoe-sofia.github.io/job-fit-web/>

---

## 它解决什么问题

投递前那 30 秒的判断，通常靠感觉：这个岗位我够不够？差在哪？改简历往哪改？

OfferFit 把这件事变成可复核的结构化输出：

- **不是让模型夸你**，而是把 JD 拆成要求项，回指你简历里的具体句子，判定「有证据 / 只有名词 / 无证据」。
- **先过硬门槛**：地点、年限、学历、核心技能、薪资。任一不过，匹配度按规则封顶，避免「加权分很高但其实根本不符合」的幻觉。
- **结论可追溯**：每条优势、缺口、风险都带原文证据，你可以自己判断它说得对不对。
- **按身份说话**：求职者拿到投递与改简历的动作，面试官拿到胜任度、风险与提问清单；同一份数据，两种读法。

## 评分口径

完整定义见 [docs/CONTRACT.md](docs/CONTRACT.md)，这里只给结论。

四个维度各自算分后按权重加权，**再按「已知权重」归一化**（某维度无证据时不计入分母，避免被扣分）：

```
加权分 = Σ(维度分 × 权重) / Σ(已知维度的权重)
```

硬性条件**不参与加权**，而是作为闸门：

- 任一硬性条件判定为 `fail` → `匹配度 = min(round(加权分), 44)`
- 只降不升：加权分本来就低于 44 时，保持原分，不会把你抬到 44
- 同时给出 `unconstrainedScore`：同一套全维度加权，**不施加封顶**，用于看「如果不卡门槛，实际水平如何」

分数到结论的映射：≥75 强匹配 / ≥60 良好 / ≥45 一般 / 其余偏弱（阈值可改，需严格递减）。

> 这套规则是**启发式的**，用于投递前的自我检查，不构成录用预测。它衡量的是「简历与这份 JD 的字面契合度」，不是你的能力。

## 两种视角

分析前先选身份，报告会按「谁在看」重组结论。**视角不参与打分**——同一份简历、同一个岗位，切换视角后匹配度、维度分、硬性条件判定一字不变，变的只是建议的取舍与措辞。

| 视角 | 决策问题 | 报告结构 |
|---|---|---|
| 我是求职者（默认） | 投不投？简历改哪？面试怎么答？ | 匹配优势 → 能力差距 → 简历优化方向 → 投递建议 → 面试准备建议 |
| 我是面试官 | 要不要面？证据够不够？风险在哪？问什么？ | 候选人胜任度 → 岗位匹配证据 → 风险点 → 面试提问建议（每条附观察点） |

实现上，`perspective` 是契约里的独立字段（见 [docs/CONTRACT.md](docs/CONTRACT.md) 第八节）；AI 模式下模型只改写措辞，结构与档位仍由本地规则给定，避免「换个视角把结论说岔」。分析完再切视角，只要输入没变，页面会就地刷新建议段落。

## 两种引擎

**本地规则引擎（默认）**：纯 JS 规则 + 关键词/年限/学历/地点/薪资比对，完全离线、结果可复现、零成本。适合大多数场景。

**AI 模型 API（可选）**：填入任意 OpenAI 兼容接口（`https://api.openai.com/v1`、DeepSeek、本地 Ollama 等），由模型生成更自然的评语。要点：

- 密钥**只存在于当前页面的内存变量**：不写 localStorage / sessionStorage，不进日志，不随结果导出。
- 发送前默认对简历脱敏（可在设置里关闭，但不建议）。
- 浏览器直连第三方接口受 **CORS** 限制，对方不允许跨域时会被拦截；线上站点为 HTTPS，接口也必须是 `https://`，否则按混合内容拦截。
- 模型返回的分数**不被采信**：本地会重算维度分与封顶逻辑，模型只负责措辞。
- JSON 解析失败会自动修复并重试一次，仍失败时提示切回本地引擎。

## 分析记录

投递决策常常要来回比：同一个岗位换个视角看一遍、改完简历再算一次。所以记录是**追加式**的——每次分析都新存一条，只在记录 id 重复时去重，绝不按岗位覆盖：

| 行为 | 记录结果 |
|---|---|
| 同一岗位再分析一次 | 新增一条，旧的仍是第 1 次、第 2 次，各自完整 |
| 分析后切换视角 | 视角变了就是另一份结论，单独新增一条，不改写上一条 |
| 刷新 / 关掉标签页 | 默认保存于本机浏览器，重新打开仍在 |
| 删除一条 | 只删这一条，同岗位其他记录不受影响 |

列表按岗位分组，组头给出该岗位的分析次数、两个视角各几条、最高分与最近时间；每条记录都带「第 N 次分析 · 视角 · 生成时间 · 引擎 · 档位 · 分数」。每条记录自身保存岗位快照（含 JD 原文）、分析视角、生成时间与完整分析结果，所以任一条都能独立打开、独立导出，不依赖「最新一次」。

「导出记录」得到 `offerfit-records-YYYY-MM-DD.json`，格式与仓库里的 `data/records.json` 一致。该文件是**只读基线**：页面启动时按 id 与本机记录合并，不会覆盖本机数据。把导出的 JSON 覆盖进去再提交，换台设备也能看到同一份记录（提交前确认不含敏感信息）。

## 隐私设计

| 承诺 | 实现 |
|---|---|
| 文件不上传 | 解析全部在浏览器内完成，无任何上传接口 |
| 密钥不落盘 | 仅存闭包变量，页面刷新即失效 |
| 简历不留存 | 分析记录不含简历原文；`localStorage` 只存配置（权重/阈值/主题）与记录，不含密钥 |
| 可一键清除 | 右上角「清除全部数据」清空配置、记录与页面状态；记录区也可单独「清除记录」 |

唯一的数据出口是你在 AI 模式下**自己填写**的接口地址。默认状态（本地引擎）下，页面只请求同源的静态资源与 `data/records.json`（仓库基线，可在部署时删掉）。

详见 [PRIVACY.md](PRIVACY.md)。

## 项目结构

```
index.html              单页应用（三段式表单 + 结果区）
serve.js                零依赖本地静态服务器（仅开发用）
启动应用.bat / .vbs      Windows 一键启动（GBK 编码）
assets/
  css/app.css           全部样式，颜色走 CSS 变量以支持明暗主题
  js/theme.js           主题读写（先于 CSS 执行，避免闪屏）
  js/privacy.js         脱敏与 HTML 转义
  js/engine.js          本地规则引擎 + 契约校验 + 提示词
  js/store.js           分析记录仓库（追加式、按岗位分组，纯函数便于测试）
  js/import.js          PDF / DOCX / TXT 解析
  js/app.js             交互、校验、渲染、导出、记录
  vendor/               pdf.js 3.11.174、mammoth（本地打包，离线可用）
data/
  records.json          记录基线：启动时按 id 与本机记录合并，可用「导出记录」覆盖
docs/
  CONTRACT.md           输入/输出契约、评分口径与记录结构
  USAGE.md              使用说明与常见问题
  DEPLOY.md             部署与国内访问方案
tests/
  smoke.test.mjs        评分口径与脱敏的冒烟测试（零依赖）
  records.test.mjs      记录追加、分组、序号、导出回读的测试
LICENSES/               第三方许可证全文
```

无 `package.json`、无构建产物：改完文件刷新即可，部署就是把目录原样托管。

## 已知限制

- 规则引擎按字面匹配，简历写得含糊时判定会偏保守——这本身是个信号：改简历比改工具更有用。
- 中文分词依赖内置词表，冷门技术名词可能识别不到，可在「技能筛选」里手动补充。
- PDF 只支持文本型文件，扫描件（图片型 PDF）提取不到文字，请改用粘贴。
- 记录保存在浏览器本机，换浏览器/换设备不会自动同步；需要跨设备请「导出记录」后替换 `data/records.json` 并提交。
- 记录条数上限 200（仅防存储无限膨胀，不按岗位限制）；存满时优先丢最旧的并在记录区提示。
- 暂无多岗位横向对比表、批量投递管理、账号体系（也不需要，那会引入后端与隐私成本）。
